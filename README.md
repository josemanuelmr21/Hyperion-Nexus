# hyperion-starter

A starter implementation of **Hyperion**, the agentic assistant for the [HyperAI IDE](https://ide.hyperai.di.uoa.gr/), written in Python. It is a minimal [FastAPI](https://fastapi.tiangolo.com/) server that listens on **port 8000**, exposes a `POST /chat` endpoint, and streams its reply back to the IDE as [Server-Sent Events](https://developer.mozilla.org/en-US/docs/Web/API/Server-sent_events). Out of the box it forwards your prompt to a `llama3.2` model and streams the answer back — your job is to turn that into a real agent.

## Prerequisites

Have the HyperAI IDE running locally (each command runs in the foreground — use one terminal per service):

1. Run the `ide-backend` Docker image:

   ```bash
   docker run --rm -p 3001:3001 -e AUTH_ENABLED=false \
     --name ide-backend donmichael/ide-backend:latest
   ```

2. Run the `ide-frontend` Docker image:

   ```bash
   docker run --rm -p 5000:80 --name ide-gui donmichael/ide-gui:latest
   ```

3. Open the IDE at <http://localhost:5000/>

## How to start

1. Clone the repository:

   ```bash
   git clone https://gitlab.eclipse.org/eclipse-research-labs/hyper-ai-project/hyperion-starter.git
   cd hyperion-starter
   ```

2. Run it locally with [uv](https://docs.astral.sh/uv/):

   ```bash
   uv run main.py
   ```

   or in Docker (the Docker image is the deliverable of the challenge):

   ```bash
   docker compose up --build
   ```

3. In the IDE, open **Hyperion** from the sidebar (the robot icon), type something, and watch the answer stream back token by token.

You can also test the endpoint without the IDE:

```bash
curl -N -X POST http://localhost:8000/chat \
  -H "Content-Type: application/json" \
  -d '{"user_id": "123e4567-e89b-12d3-a456-426614174000", "text": "hello"}'
```

## The protocol

On every user prompt the IDE sends:

```json
{ "user_id": "...", "text": "..." }
```

- `user_id` — a UUID automatically generated by the IDE; use it to keep per-user session memory
- `text` — the text the user typed in the chat

Your response must be streamed as Server-Sent Events. Each event is a `data:` line with a JSON payload followed by a blank line; the IDE reads the `response` field and appends it to the chat as it arrives:

```
data: {"response": "Hello "}

data: {"response": "world"}

data: [DONE]
```

Note that each `response` chunk is an **increment**, not the accumulated text — send only the new part. The final `data: [DONE]` is optional but recommended.

## Helper function

`read_file`

This function reads a file from the `ide-backend`. It takes the path as its
argument and returns the contents of the file, or raises `ReadFileError`. Use it
when you need to read a file and give its contents to the agent.

```python
from helpers import read_file

content = await read_file("app.yaml")           # just the name - the backend finds it
content = await read_file("demo/sub/app.yaml")  # or the full path
```

> **Note**
>
> The address comes from `IDE_BACKEND_URL`. Running locally it is
> `http://localhost:3001/api`; when you run the agent as a Docker container it
> has to be `http://host.docker.internal:3001/api`. Both are already set in the
> code, so you do not have to do anything else.

## Add your agentic code

You can use your favourite framework. We recommend:

- [LangChain](https://python.langchain.com/) / [LangGraph](https://langchain-ai.github.io/langgraph/)
- [PydanticAI](https://ai.pydantic.dev/)

but any framework works — for example [LlamaIndex](https://docs.llamaindex.ai/), or plain calls to an OpenAI-compatible API.

Add dependencies with `uv add <package>`

Keep in mind: the IDE frontend calls your service straight from the browser, so the CORS middleware in `main.py` must stay enabled.
